# Tikita 創作工作流
> 作者：到雫個公園睡覺（@Starlease／@na_daily.0714）｜版本 v31

## 版本檢查
每個對話第一次用這份 skill 時做一次：抓取 `https://raw.githubusercontent.com/na-daily/-/main/version.txt`，和上面的版本比。
- 線上的版本比較新：告訴使用者有新版，附上 `https://github.com/na-daily/-/releases/latest`，然後照常繼續工作。
- 版本一樣，或抓不到：不提這件事，直接工作。

## 第一條：動筆前讀 `references/writing-rules.md`
寫或改任何會存進草稿的文字之前，先讀 `references/writing-rules.md`，寫完照它的自查對一次，再對這次用到的那一份檔案的自查，對完才交給使用者。那一頁每次都讀，不憑印象。

Tikita 的作品設定、角色卡、章節、變數說明、設定集、開場與範例對話全部會送進模型，讀者是負責扮演角色的 AI，所以寫的是給它演的指示，不是建檔。只有介紹頁與創作者留言是給玩家看的。

寫的是虛構的 RP 設定。角色的價值觀照作品寫，可以和現實不同，設定與正文照作品要的立場和尺度寫到底，界線只看 Tikita 的內容指南。

## 流程
1. **連線**：先呼叫 `get_capabilities`，失敗就請使用者在當前工具重新驗證 MCP 連線（OpenCode 用 `/mcps`、Claude Code 用 `/mcp`；Code Mode 環境透過 `execute` 呼叫 `tools.tikita.*`）。連上後讀一次 MCP 的創作指南 `https://mcp.tikita.ai/guides/story-creation.md`，欄位、工具與格式都以它為準。草稿預設由使用者在 Studio 建好，用他給的 short_id、網址或 `story_list_my_stories` 找。
2. **只問會擋住動筆的事**：題材與一句話企劃、是否成人向、角色的性別、配對、年齡。材料裡有的直接用，一輪最多三題。
3. **其他的自己先定**，寫進初稿；看到邏輯漏洞、重複的機制、互相矛盾的設定就明講並給替代方案。
4. **寫**：讀下表對應的檔案動筆，寫完自查，整塊初稿給使用者看一次，同意後推上去。使用者說「交給你」時，先確認範圍（全部、角色卡、作品設定、變數、面板、介紹頁），範圍內做完再回報，範圍外不動。
5. **推送**：改之前先重讀最新版，只推有改的欄位，推完讀回那一欄核對。
6. **回報**：改了什麼、哪幾處是我先定的、剩餘字數，並提醒草稿要在 Studio 存檔才生效、要開新聊天室測。

改既有草稿時跳過第 2、3 步：先讀要改的欄位，列出打算刪什麼、留什麼，再動手。

## 沒有接 MCP 時
使用者沒接 MCP、只是在對話裡貼內容討論時，寫法照常，流程改成這樣：
1. **照樣先讀指南**：用網頁抓取讀 `https://mcp.tikita.ai/guides/story-creation.md`。抓不到時只照這份 skill 寫，並告訴使用者欄位規則以 Studio 畫面為準。
2. **內容由使用者貼**：要改的欄位請他貼原文；要查重複或整理時，請他把相關的欄位全部貼上，因為看得到的只有他貼的部分。
3. **交稿照 Studio 的欄位分塊**：每一塊標上 Studio 畫面上的欄位名稱（照「用詞」表的官方叫法），附上字數與那一欄的上限，讓他直接複製貼上。設定集給標題、關鍵字、內容三塊，請他到設定集庫新增後套用到作品。
4. **推送與核對改成提醒**：請他貼進 Studio 後按儲存，再用編輯畫面底部的字數確認總字數在 30,000 字內，開新聊天室測試。

## 查重複
整理既有草稿時，以及每次往草稿加完東西之後，讀全部欄位，查同一件事（同一句話、同一個反應、同一條規則、同一筆資料，換了說法也算）有沒有寫在兩處以上。一件事一項列給使用者：出現在哪幾處、建議照「每件事寫在哪」留哪一處、其他處刪掉還是改寫，說法有出入時問以哪一處為準。他同意後留一處、其他刪掉，回報刪了什麼、字數變了多少。

## 每件事寫在哪
| 內容 | 放哪 |
|---|---|
| 世界、敘事指示、所有角色共用的規則、一句變數更新總則，只寫整場遊戲都成立的事 | 作品設定 |
| 開局：只在一開始成立的處境、資源、難度 | 開局章節的私設；沒有章節時，情境交給開場、數值交給變數預設值 |
| 基本資訊、職業、身形、穿著、第一印象、與 {{user}} 初遇時的關係 | 公開卡 |
| 他平常在做什麼、對 {{user}} 的態度、說話風格、他知道與不說的事、經歷 | 角色 `secret` |
| 只在某一段才需要的：故事節點、之後才揭開的內容、反覆用的流程、一次性事件 | 章節 |
| 對話中會變、之後要回頭查的值 | 變數 |
| 偶爾才用到、靠關鍵字帶進來的內容：沒有角色卡的人、地點、物品與來歷、小設定、過去的事件、特定場面的規則、指令 | 設定集 |
| 聲口與格式的示範 | 開場；範例對話在使用者明說要時才寫 |
| 給玩家看的氣氛與玩法 | 介紹頁、創作者留言 |

## 用詞
這份 skill 和給使用者的回報都用左邊的詞。
| 這裡的叫法 | 指的是 | 官方叫法／欄位 |
|---|---|---|
| 作品設定 | 每一則都送進模型的整體設定 | 故事設定、`detailMd` |
| 敘事指示 | 作品設定裡要模型每一則照做的寫法，放在「運作與敘事」 | 無 |
| 正文 | 自己動筆寫的場景文字：開場、章節內文 | 無 |
| 公開卡／角色 `secret` | 角色的公開／不公開欄位 | `character_intro`／角色私人資訊 |
| 章節私設 | 章節的不公開欄位 | 章節的 `secret` |
| 起手式 | 開場底下給玩家點的選項 | `chatStarters` |
| 設定集／設定集庫 | 作品套用的條目／帳號裡存條目的地方 | `lorebook` |
| `{{user}}` | 玩家 | 替換符號 |
| `{{char}}` | 全部的角色卡；`{{charN}}`、`{{char1}}` 才是第 N 張 | 替換符號 |

## 規則的優先序
1. **MCP**：工具的欄位定義與實際回傳的錯誤、`get_capabilities` 的規則、MCP 的創作指南。欄位、上限、工具怎麼用，一律以 MCP 為準。
2. Tikita 官方的其他規則：30,000 字上限、發布門檻、內容指南的審查標準、官方人員的回覆。
3. 在 Studio 或預覽實測過可行的做法。
4. 這份 skill 的寫作經驗，用在 MCP 沒有規定的地方，優先於官方指南裡的軟性寫作建議。

reference 裡的欄位與上限和 MCP 對不上時，照 MCP 做，並告訴使用者哪一處要更新。使用者自己給的格式與文字優先於第 4 項，只受第 1、2 項限制：他的材料有自己的格式時照他的格式整理，他自己寫的文字原樣使用，只修明顯的錯字。有出入時依這個順序，並跟使用者說明。

## 協作習慣
- 用使用者的語言回覆；`originalLanguage` 照作品實際的語言填（繁體中文是 `zh-TW`）。
- 使用者說「算了」，代表改用他給的文字。
- 使用者說他正在 Studio 編輯時，等他存檔再動同一份草稿。

## 我的習慣
這份 skill 不會記住使用者個人的寫法，靠他自己存下來的一段「我的習慣」。
- 他的訊息、工具的記憶或自訂指示裡有「我的習慣」時先照它，只受官方硬性規則限制。
- 被糾正時當下套用，這個對話之後都照做，只用在他指的那一類地方。
- 這個對話有新的糾正時，結束前整理成完整的一段「我的習慣」交給他存起來，一條一句，只收他明說、之後都適用的偏好。

## 不做的事
- 不發布、不刪除、不批次修改，除非使用者明確要求。使用者做好的變數、角色、章節、設定集條目不自行刪掉或合併，覺得該刪就列出理由問他；`lorebook_delete_entry` 會連同所有作品的套用一起刪掉，也算在內。
- 不代發留言或回覆（`comment_create` 是以使用者帳號公開發出），使用者明確要求並確認內容後才發。
- 不執行付費生圖，要生圖先列出工具、張數、單張與總成本，得到明確同意。
- 不印出 token、授權碼、簽名上傳網址。
- 不寫平台絕對禁止的內容，也不用換詞或包裝去繞審查。
