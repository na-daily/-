# Tikita 創作工作流
> 作者：到雫個公園睡覺（@Starlease／@na_daily.0714）｜版本 v20

## 第一條：動筆前讀 `references/writing-rules.md`
寫或改任何會存進草稿的文字（作品設定、角色卡、開場、範例對話、章節、變數說明、設定集、介紹頁）之前，先讀 `references/writing-rules.md`，寫完照它最後的自查逐條對，對完才交給使用者。那一頁是這套寫法的全部規則，只有一頁，每次都讀，不憑印象。

Tikita 的作品設定、角色卡、章節、變數說明、設定集、開場與範例對話全部會送進模型，讀者是負責扮演角色的 AI。寫的是給它演的指示，不是建檔。只有介紹頁與創作者留言是給玩家看的，AI 不會讀。

## 流程
1. **連線**：先呼叫 `get_capabilities`，失敗就請使用者在當前工具重新驗證 MCP 連線（OpenCode 用 `/mcps`、Claude Code 用 `/mcp`）。Code Mode 環境（如 OpenCode）透過 `execute` 呼叫 `tools.tikita.*`。
   - 預設由使用者先在 Studio 建好草稿。他明說要新建時才用 `story_create_draft`，那時受工具的必填下限限制。
   - 用他給的 short_id、網址或 `story_list_my_stories` 找草稿，不叫他重貼已存的內容。
2. **只問會擋住動筆的事**：題材與一句話企劃、是否成人向、角色的性別、配對、年齡。使用者的材料裡已經有的不問。一輪問完，最多三題。
3. **其他的自己先定**，寫進初稿，並在交稿時列出「這幾處是我先定的」讓使用者改。有邏輯漏洞、重複的機制、互相矛盾的設定就明講並給替代方案。
4. **寫**：讀 `writing-rules.md` 和下表對應的檔案，寫完自查。使用者的材料有自己的格式時照他的格式整理，這套工作流的格式只用在他沒給格式的地方。他自己寫的文字原樣使用，只修明顯的錯字，開場裡當主詞的 {{user}} 換成「你」。
5. **整塊初稿給使用者看一次**，同意後推上去。使用者說「交給你」時，先確認範圍（全部、角色卡、作品設定、變數、面板、介紹頁），範圍內不等確認，做完再回報；範圍外不動。
6. **推送**：改之前先重讀最新版（使用者會在 Studio 手改，存檔後 item id 會變）。只推有改的欄位，推完讀回那一欄核對。大量寫入前看 `workspace_get_content_budget`，上限 30,000 字。
7. **回報**：改了什麼、哪幾處是我先定的、剩餘字數。草稿要使用者在 Studio 存檔才生效，要開新聊天室測。

改既有草稿時跳過第 2、3 步：先讀要改的欄位，列出打算刪什麼、留什麼，再動手。

## 查重複
整理既有草稿時，以及每次往草稿加完東西之後，整份查一次同一件事有沒有寫在兩處以上。
1. **讀全部欄位**：作品設定、每張角色卡的公開卡與 `secret`、章節私設、變數的說明與範圍說明、設定集、開場。
2. **找重複**：同一句話、同一個反應或說法、同一條規則、同一筆資料（年齡、地點、關係）。換了說法講同一件事也算。
3. **列給使用者**，一件事一項：這件事是什麼、出現在哪幾處（欄位與原句）、建議留哪一處（照下一節「每件事寫在哪」）、其他處刪掉還是改寫。幾處的說法有出入時標出來，問以哪一處為準。
4. **使用者同意後整理**：留一處，其他刪掉。被刪的那一處因此不完整時，換一個角度補一句，不照抄。整理完回報刪了什麼、字數變了多少。

使用者把範圍交給你時，範圍內直接整理，做完照第 3 步的格式回報。

## 每件事寫在哪
每件事只寫一處，各區讀起來自己完整，不寫「見某處」這種指路。重複是最常見的問題。

| 內容 | 放哪 |
|---|---|
| 世界、敘事與文風、所有角色共用的規則、一句變數更新總則。只寫整場遊戲都成立的事 | 作品設定 `detailMd` |
| 開局：只在一開始成立的狀態、資源、難度、各種開局的差異 | 綁定的開局章節的私設；沒有綁章節時交給開場與變數預設值。不寫進作品設定 |
| 基本資訊、職業、身形、穿著、首先能感受到的性格、與 {{user}} 初遇時的關係 | 角色公開卡 `character_intro` |
| 經歷與它留下的心境、對 {{user}} 的態度與反應、他知道什麼與不主動說的事、說話風格 | 角色 `secret` |
| 之後才揭開的內容、會反覆用的功能區塊（流程、抽選表）、只用一次的關卡或特殊事件、開局 | 章節私設（內文只寫「保密」）；沒有這類內容就不做章節 |
| 對話中會變、之後要回頭查的值，以及它的格式與更新條件 | 變數 |
| 沒有角色卡的角色（濃縮角色設定）、物品設定、地點設定（佈局）、細節補充 | 設定集 |
| 聲口與格式的示範 | 開場。範例對話預設不放（裡面的行為、食物、飲料會被模型一直拿來用），使用者明說要才寫 |
| 給玩家看的氣氛與玩法，不洩漏秘密。每一句重新寫，不從設定和開場複製貼上 | 介紹頁、創作者留言（AI 不讀） |

## 用詞
這份 skill 和交給使用者的回報都用左邊的詞，同一個東西只有一個名字。右邊是官方畫面或欄位上的叫法，只用來對照。

| 這裡的叫法 | 指的是 | 官方叫法／欄位 |
|---|---|---|
| 作品設定 | 每一則都送進模型的整體設定 | 故事設定、`detailMd` |
| 公開卡 | 角色的公開欄位 | 角色公開資訊、`character_intro` |
| 角色 `secret` | 角色的不公開欄位 | 角色私人資訊 |
| 章節私設 | 章節的不公開欄位 | 章節私人設定、章節的 `secret` |
| 開場 | 聊天室的第一則 | 首則訊息、開場白、`openings` |
| 起手式 | 開場底下給玩家點的選項 | 對話開場提示、`chatStarters` |
| 範例對話 | 示範用的對話 | 對話範例、`dialogs` |
| 介紹頁 | 給玩家看的作品介紹 | 故事介紹、`introMd`／`introHtml` |
| 狀態面板 | 平台顯示變數的那一塊 | 狀態欄、狀態窗、`variableViewHtml` |
| 畫面版型 | 模型在回覆裡用程式碼區塊排出來的固定畫面（平台介面、彈幕、系統視窗） | 無 |
| 設定集／設定集庫 | 作品套用的條目／帳號裡存條目的地方 | `lorebook` |
| `{{char}}` | 全部的角色卡。`{{charN}}`、`{{char1}}` 才是第 N 張 | 替換符號 |

## 依任務讀哪份
各檔案之間不互相指路，要一起讀的檔案都列在這張表。同一列的檔案全部讀完再動筆。

| 任務 | 讀 |
|---|---|
| **任何寫作**（每次都讀） | `references/writing-rules.md` |
| **開場** | `writing-rules.md` 第二組 ＋ `references/openings-and-public.md` 的「開場」（格式不照做會壞掉）＋ `references/style.md` 的「活場接龍」 |
| **角色卡**：要素與格式、狀態與附屬存在、NPC 簡版 | `writing-rules.md` 第三組 ＋ `references/character-cards.md`。使用者用標籤描述性格、或要陰暗的底色時加 `references/personality-tags.md`；成人向的慾望與黑暗向加 `references/safety-and-rating.md` 第二、三節 |
| **世界觀與作品設定**：骨架、各項規則、設定集、秘密與揭露 | `writing-rules.md` 第四組 ＋ `references/world-and-lore.md`。寫「運作與敘事」「親密時的描寫」時加 `references/style.md` |
| **文風**：固定的一塊，加上看作品才加的（內心的寫法、角色的主動性與認知、段落的排法、雙線、親密時的描寫） | `references/style.md` |
| **變數**：分三種（不需要、玩家不需要知道、給玩家看）、選類型與英文名稱、文字變數怎麼合併、規則與引用、說明怎麼寫、好感與關係階段、整理既有的變數 | `writing-rules.md` 第五組 ＋ `references/variables.md`。做狀態面板時加 `references/panel.md`；有玩家不需要知道的變數時加 `references/style.md` 的「角色的主動性與認知」 |
| **章節**：用途、切換條件、進行模式、開場綁哪一章 | `writing-rules.md` 第五組 ＋ `references/episodes.md` |
| **模擬器類作品**：對象格、帳本、動態角色的通用卡、介面型角色、機制與經濟 | `variables.md` 的「模擬器類作品才用」＋ `world-and-lore.md` 的「機制、數值、經濟」 |
| **公開區**：起手式、範例對話、推薦角色模板、標題標語、介紹頁 | `references/openings-and-public.md`。寫公開區文字前加 `references/safety-and-rating.md` 第四節 |
| **平台規則**：欄位上限、30,000 字預算、發布條件、測試對話、公開範圍、創作者留言、分類、官方指南摘要、Cinema | `references/platform.md` |
| **工具與圖庫**：編輯工具怎麼選、陣列取代的坑、開場的鏡像欄位、圖庫與上傳、留言與貼文 | `references/tools.md`。圖片尺度與遮蔽規格加 `references/safety-and-rating.md` 第五節 |
| **分級與審查**：審查標準、公開區用語、二次創作、處置與申訴 | `references/safety-and-rating.md` |

## 規則的優先序
1. Tikita 官方硬性規則：MCP 工具 schema 與實際回傳的錯誤、欄位與 30,000 字硬上限、發布門檻、內容指南審查標準。
2. 在 Studio 或預覽實測過可行的做法（例如章節與範例對話非發布必填）。
3. 這套工作流的寫作與結構做法：`writing-rules.md` 與各檔標明是做法的部分（**優先於官方指南裡的軟性寫作建議**，例如開場一律用「你」不寫 `{{user}}`、不拿章節排主線且內文只寫「保密」、預設不放範例對話）。

有出入時依這個順序，並跟使用者說明。使用者自己給的格式與文字優先於第 3 項，只受第 1 項限制；和 `writing-rules.md` 開頭那四條沒有例外的規則衝突時，先問他要怎麼處理，再整理。官方規則會改版：MCP 內容核對於 2026-11-13（build `bb4d921067`），內容指南依 2026-11-05 修訂版核對，Studio 說明整理於 2026-10-17。`get_capabilities` 回傳的 build 不同時，用當前環境的 MCP 資源讀取工具或 HTTP 抓取重讀 `https://mcp.tikita.ai/guides/story-creation.md`。工具報錯與 reference 不符時以工具報錯為準。

寫公開區文字前看今天日期：審查規則在 2026-11-14 與 2026-11-19 各有一次變動（`references/safety-and-rating.md`）。

## 協作習慣
- 用使用者的語言回覆；作品語言 `originalLanguage` 照作品實際的語言填（繁體中文是 `zh-TW`）。這份 skill 的寫法是以繁體中文作品為準寫的。
- 不替使用者決定沒指定的性別、配對、年齡。
- 使用者說「算了」，代表改用他給的文字。
- 使用者正在 Studio 編輯時，不同時用 MCP 改同一份草稿。
- 使用者糾正寫法時，把那一條寫進 `references/writing-rules.md` 對應的一組，寫成通用的做法。

## 不做的事
- 不發布、不刪除、不批次修改，除非使用者明確要求。使用者做好的變數、角色、章節、設定集條目不自行刪掉或合併；覺得該刪就列出理由問他，他把那一塊交給你時才直接動。`lorebook_delete_entry` 會連同所有作品的套用一起刪掉，也算在內。
- 不代發留言或回覆（`comment_create` 是以使用者帳號公開發出）；使用者明確要求並確認內容後才發。貼文工具只建草稿。
- 不執行付費生圖。要生圖必須先列出工具、張數、單張成本、總成本，得到明確同意。
- 不印出 token、授權碼、簽名上傳網址。
- 不寫平台絕對禁止的內容，也不用換詞或包裝去繞審查。
