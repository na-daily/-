# 變數
> 這套工作流的做法。欄位上限照平台規範，變數的語法以 Studio 的說明頁為準。

變數記的是對話中會變、之後要回頭查的值，整部作品最多 10 個。照下面的步驟做。

## 1. 決定記什麼
寫變數時，先讀完作品，從下面挑出作品真的有的，最多提五個給作者，每個用一句話說加了它遊戲會多出什麼，只做作者選的。
- **作品的核心**：標題或簡介裡講的那樣東西，例如一件物品、一份約定、一段進程。
- **角色自己的生活**：他手上在忙的事與期限、他下一個想要的東西。
- **角色的心結或週期**：他那個毛病現在多嚴重、身體或情緒的週期走到哪。
- **角色此刻**：動作、藏不住的反應、衣著、沒說出口的話。
- **壓力與期限**：債、租金、截止日、下一個固定活動。
- **世界怎麼看玩家**：名聲、評級、人氣。
- **外面的世界**：傳聞、別處的動向、逼近的威脅。
- **誰知道什麼**：秘密揭開到哪、誰握有什麼。
- **待辦與約定**：答應了還沒做的事、還沒執行的處罰。
- **玩家反覆做的事**：有玩法的作品，把那件事用什麼做、耗掉什麼、得到什麼收進同一個變數。

每一樣再分成三種：
- **不需要變數**：不會變的（菜單、價目）寫進作品設定；有角色卡的角色，卡上已經有的外貌、經歷不重複記。遊戲中才生成的角色沒有卡，他的外貌與底細記在變數。
- **玩家不需要知道的**：還沒揭露的底細、對方握有的東西、計次用的計數，放進 Hidden 這類變數，不進狀態面板，所以有這種變數的作品，面板用自訂 HTML。作品設定的「運作與敘事」要加這一句，括號換成實際的內容：「Hidden 記的是 {{user}} 還沒知道的事，旁白與台詞只寫 {{user}} 已經看到、聽到的部分，（哪幾行）在（條件）時才寫出來。」哪個角色知道哪一行，寫在他角色卡的「認知範圍」。
- **給玩家看的**：回覆序號、時間地點、天氣、月相、錢、好感、衣著、約定這類玩家要看的，放進狀態面板。

## 2. 選類型與名稱
- **布林與列舉**只能透過 MCP 設定，Studio 畫面上選不到：布林記是或否（已見過、已解鎖），列舉記固定幾個狀態裡的一個（未察覺、起疑、已確認）。
- **數字變數**用來追蹤單一個值（好感、信任、體力、金額），可以在面板做成量表。
- **文字變數**用在要合併好幾件事、要多行、要帶狀態詞的時候。文字變數照主體合併，一個主體一個變數、一行一件事，常見的主體是一個角色的狀態（{{user}} 自己也是一個）、其他認識的人的名單、一個地點的經營狀態。同一個角色除了好感還要記別的事時，好感併進他的文字變數成為其中一行。
- **名稱用英文**，10 個字元內、不含空格，同類的加編號（`Scene`、`Player`、`Shop`、`Trust`、`Char1`、`Roster`、`Hidden`）。名稱是面板和規則引用它的依據，定了就不隨便改。
- 回覆序號預設放在 Scene 的第一行，每則加 1，也可以獨立開一個 `Turn`；它也是定期事件與隨機事件的節拍。

## 3. 寫說明
說明是模型更新這個變數時唯一的依據，所以這個變數的規則全部寫在它自己的說明裡。常見的寫法是三段：【用途】一句話記什麼；【樣子】把整個變數的版型照實際的樣子排出來；【每一行】用有序列表，第 N 項對應第 N 行，寫這一行放什麼、能填哪些值、什麼時候改。一套規則同時管好幾行時另開一塊，例如【好感】【揭露】【結算】。

範例（虛構）：
```
名稱 Shop｜文字
【用途】{{user}} 這間店的錢、食材、店租，和答應了還沒做完的事。
【樣子】固定四行，用真正的換行分隔，不要使用\ n：
💰 現金 N 元｜今日營收 N 元
🥬 食材：…
🏠 店租：月租 N 元｜每月 D 日繳｜繳款狀態
📌 約定：…
【每一行】
1. 都寫目前的總值。客人結帳時加進現金和今日營收，進貨、繳租時從現金扣，日期換到隔天時今日營收歸零。
2. 只寫快用完和已經用完的食材，用「、」隔開，都夠時寫「充足」。
3. 繳款狀態寫「剩 N 天」或「逾期」，日期每換一天把 N 減 1，到 0 時還沒付就改成逾期，付清時改回「剩 30 天」。
4. 一筆寫成「對象：內容（期限）」，用「；」隔開，最多五筆，答應時加上，完成、取消或過期時刪掉。
```

寫說明時用得上的經驗：
- 玩家自己決定的欄位寫欄位名（店名、暱稱），因為模型看到具體的例子會照抄。
- 多行文字變數的【樣子】寫「用真正的換行分隔，不要使用\ n」（反斜線與 n 中間有空格），防模型寫出字面的換行符號。
- 每則都要重寫的行越少越好，其他行寫明在什麼事發生時才改，因為每則要重寫的行一多，模型就會漏更新或整串照抄上一則。
- 約定、欠款、對方握有的東西、失去的記憶這類會被忘記的事，要有一行記著；要數次數的規則，給它一個計數的位置（「罰過 N 次」）。
- 同一份資料要出現在兩個變數時，一邊留著完整的一份，另一邊照抄並標「（已揭露）」這類記號，因為「移過去再刪掉」模型很容易漏一步。
- 有多種開局時，預設值放最常用的那個，其他開局的差異寫在開局章節的私設。

數字變數的說明寫【用途】與【規則】（什麼事加減多少），範圍說明一個區間一項，寫這個區間裡他的感受與傾向。

## 4. 好感與關係階段
- **好感區間寫成心境**：✕「80 以上戀人」→ ○「80 以上是愛上了」，因為區間寫成關係，數字一到模型就自動確認。作品設定的「運作與敘事」要配上這一句：「{{char}} 喜歡上 {{user}} 時，會照自己的性格讓對方知道，交往、結婚也是他自己會提的事；兩人在告白並得到回應時才成為戀人，在那之前的親密不改變原本的關係。」
- 好漲還是難漲由角色的性格與經歷決定，寫在角色卡。
- **關係階段需要才設**，用看得見的事實命名（「還沒認定」「認定之後」），和角色卡「與 {{user}}」底下的小節同名。它記的是目前的關係，判定寫一件看得見的事。

## 5. 接上作品設定與面板
- 作品設定的「變數」一節放一句更新總則，列出全部變數的名稱：「每則回覆結尾更新 Scene、Trust、Shop，照各自的說明寫目前的總值。」
- 別處提到變數時寫英文名稱接那一行的名字，例如「Trust 到達 70 時」「Shop 的店租逾期時」「Scene 的回覆序號個位數是 0 時」。
- 名稱改了、變數增減了，更新總則、狀態面板、作品設定、章節和別的變數的說明一起改。
- 寫完請使用者用便宜的模型開新對話測十則，看格式有沒有跑掉、序號有沒有每則加一、數字有沒有照規則動。

## 整理既有的變數
每個變數對三件事：它是三種的哪一種、類型對不對、算式會不會太多。要改的一項一項列給使用者：哪個變數、為什麼、改成什麼樣子。

## 自查
- 玩家不需要知道的變數有沒有被放進狀態面板？
- 更新總則列的名稱和實際的變數一致嗎？
