# 變數
> 「官方限制」一節是官方規則，其餘是這套工作流的做法。

照順序讀：先找出這部作品可以記什麼，再分種類，再選類型與名稱，再寫規則與說明。

## 先找出這部作品可以記什麼
作者常常不知道自己的作品能用哪些變數，所以動手前由 AI 主動找，不等他開口：
1. 讀完作品，拿下表的十類逐一對，這部作品有這一類的東西才列為候選。
2. 候選最多提五個，每個用一句話說加了它遊戲會多出什麼，並標出最建議先做的兩三個。模擬器類作品候選多時分批提，一批還是最多五個。
3. 只做作者選的，回報時列出「這幾樣先留著，之後要加可以再說」。
4. 先看前兩類。好感和錢是最常見的候選，這部作品用得到才列。

| 類型 | 記什麼 | 大概怎麼做 |
|---|---|---|
| 作品的核心 | 標題或簡介裡講的那樣東西：一件物品、一份約定、一段進程 | 自己一個文字變數。有進度的寫階段或累計值，每一階寫一件看得見的事當條件；是清單的一條一行，設上限，寫明誰能加、什麼時候改 |
| 角色自己的生活 | 他手上在忙的事與期限、他今天的小事、他下一個想要的東西 | 併進他的狀態變數，或另開一個。期限用倒數；每天換的小事照日期或回覆序號的個位數查表；想要的東西在得到之後重新指定 |
| 角色的心結或週期 | 他那個毛病現在多嚴重、身體或情緒的週期走到哪 | 心結用一個數值，寫什麼事加減，各區間的心境寫在角色卡；週期寫狀態詞加剩幾天，日期每換一天減 1 |
| 角色此刻 | 動作與姿勢、藏不住的反應、衣著、沒說出口的話 | 他的狀態變數裡各一行。動作與心聲每則重寫，衣著在換的時候才改 |
| 壓力與期限 | 債、租金、截止日、下一個固定活動 | 寫對象、剩多少、到期日或剩幾天；到期沒完成會怎樣，寫成一條規則 |
| 世界怎麼看玩家 | 名聲、評級、人氣 | 一個數值或階段，寫被多少人看見的什麼事會加減；各區間寫旁人因此怎麼對待玩家 |
| 外面的世界 | 傳聞、別處的動向、逼近的威脅 | 一行一句。給玩家看的照場合重寫；玩家不需要知道的用固定幾個狀態詞，照劇情改 |
| 誰知道什麼 | 秘密揭開到哪、誰握有什麼 | 一串不可回退的狀態詞，或一條一行的帳本（內容、持有人、狀態）；玩家不需要知道的另外放 |
| 待辦與約定 | 答應了還沒做的事、輪到誰、還沒執行的處罰 | 照「常用的行」的約定清單寫 |
| 玩家反覆做的事 | 有玩法的作品才需要 | 把那件事拆成五樣：用什麼做、每次耗掉什麼、做完得到什麼、放在哪、之後拿去哪。五樣收進同一個變數，一行一樣，不各開一個 |

候選一樣要過「先分三種」的判準，找完再照下面的順序做。

## 先分三種
每一樣想記的東西，先分清它是哪一種，再決定要不要開變數、要不要給玩家看。

1. **不需要變數**
   - 不會變的：菜單、價目、樓層，寫進作品設定。
   - 當場寫就好的：天氣、氣氛。
   - 角色卡已經有的：外貌、經歷。
2. **玩家不需要知道的變數**：模型之後要回頭查，但玩家看了沒有用，或會先知道不該知道的事。
   - 還沒揭露的底細、對方手上握有的東西、計次用的計數（罰過幾次）。
   - **裡面的內容要等條件到了才寫出來，靠認知來寫**：誰知道哪一行、什麼條件才說，寫在敘事指示和角色卡。
   - 面板只放給玩家看的變數。基本模式會列出全部變數，所以有這種變數的作品，面板用自訂 HTML。
3. **給玩家看的變數**：玩家做決定時要看的。
   - 回覆序號、時間地點、錢與資源、好感與關係階段、衣著、約定。
   - 放進狀態面板，版型排成玩家一眼看得懂的樣子。

新開變數的判準：這個值會變，而且之後有人要回頭查。兩個條件都符合才開。整部作品最多 10 個，用得到幾個就開幾個。

## 選類型與取名
1. **數字變數**：能做的事少，只拿來簡單追蹤單一個值（好感、信任、體力、金額、次數）。規則只有加減，一個數字只記一件事。它可以設範圍說明，也可以在狀態面板做成量表。
2. **文字變數**：其他全部。需要合併好幾件事、要多行、要帶狀態詞、或有自己的格式時，一律用文字變數。
3. 只追蹤一個好感就用數字變數。同一個角色還要記階段、衣著、心聲時，全部併進他的文字變數，好感變成其中一行，各區間的態度寫在說明的【好感】規則塊。
4. **名稱用英文**，10 個字元內、不含空格，取中性的詞，同類的加編號：`Scene`、`Player`、`Shop`、`Trust`、`Char1`、`Roster`、`Hidden`。名稱是面板和規則引用它的依據，定了就不隨便改；要給玩家看的中文標籤寫在狀態面板的 HTML 裡。

## 文字變數怎麼合併
合併照主體分：一個主體一個變數，一行一件事。同一個主體的事放在一起，一個變數至少管好幾件事。

常見的三種主體：
1. **單一角色的狀態**：關係階段、好感、衣著、當下在做什麼、心聲。{{user}} 自己的狀態（身分、衣著、身體、持有物）也是一個。
2. **名單**：其他認識的人，一人一行。
3. **一個地點的經營狀態**：錢、庫存、租金、答應了還沒做完的事。

常用的行：
1. **回覆序號**：預設放在 Scene 變數（時間地點）的第一行，每則加 1。也可以獨立開一個數字變數 `Turn`，多佔一個名額，但面板與規則能直接引用。它給玩家看，也是創作者做定期事件與隨機事件的節拍，引用方式在「怎麼引用」。
2. **衣著**：角色和 {{user}} 的狀態變數各放一行，寫穿什麼、衣服的狀況。
3. **概括的指標**：角色狀態用一個值涵蓋多種情況（理智程度、週期的提示）。
4. **約定清單**：放在 {{user}} 狀態或經營狀態的最後一行。一筆寫成「對象：內容（期限）」，用「；」隔開，設上限（五筆）。答應時加上；完成、取消或過期時刪掉；到期當天對方會來提。
5. **身上與住處**：一行一件事，順序照玩家看的習慣：住處、衣著、配件、身體、運作中的設備、全部的設備。
   - 「運作中」和「全部」分兩行：前者只列此刻在動的與狀態，後者只列名稱。
   - 身體那一行除了當下的狀態，也記會一直留著的東西（痕跡、失去的記憶），寫明留到什麼時候。
   - 住處帶繳租日與狀態（剩 N 天、逾期），日期每換一天把 N 減 1。

**每則都要重寫的行越少越好**。整部作品裡每則重寫的只留少數幾行（回覆序號、當下的動作、心聲），其他行只在事情發生時才改，並在說明裡寫明什麼時候改。每則要重寫的行一多，模型就會漏更新或整串照抄上一則。

會被忘記的事要有地方記：約定、欠款、對方握有的東西、失去的記憶，沒有一行記著，模型過幾則就忘。

## 規則怎麼寫
**變數做得到的事**（挑作品用得到的）
| 要做的事 | 寫法 |
|---|---|
| 倒數 | 寫「剩 N 天」或「剩 N 則」，每換一天或每則回覆減 1，到 0 時發生該發生的事 |
| 累計 | 每發生一次加一個寫死的數，照表對出等級或輕重 |
| 狀態切換 | 一串固定的狀態詞（已繳／逾期），每個轉換寫一個條件 |
| 排程與待辦 | 照「常用的行」的約定清單寫；排定的次數做完一次減一 |
| 定期與隨機事件 | 照回覆序號的個位數查表（「怎麼引用」） |

1. **用事件觸發**：「人數越高越可能有新角色」模型看不出什麼時候該做，改成看得到的事件：升級時、上榜時、回覆序號的個位數是 0 時。
2. **要定期發生的事，綁在每則都會更新的計數上**：用回覆序號的個位數當節拍最穩。兩件定期的事用不同的數字錯開。
3. **要數次數的規則，給它一個計數的位置**：「第一次輕、第二次中、第三次重」要有一行「罰過 N 次」，否則沒有人在數。
4. **用抄的**：一份資料要在兩個變數之間出現時，讓一邊永遠留著完整的一份，另一邊照抄，用「（已揭露）」這類記號標狀態。「移過去再從這裡刪掉、換回來再搬回去」，模型很容易漏一步。
5. **永遠寫目前的總值**；文字變數整串改寫。
6. **一次性事件用「進程」記錄**，只增不減；想隱晦就用數字標記，對應表放說明裡。

## 怎麼引用
變數取了英文名稱之後，別處都用這個名稱指它。

1. **狀態面板**：`{{Trust}}` 顯示值；數字變數用 `{{Trust:numeric}}` 做量表；要照數值決定顯示什麼時用條件，例如 `{{#gte Count 2}}…`。多行文字變數的那一格加 `white-space:pre-line`。
2. **作品設定、章節私設、切換條件、其他變數的說明**：直接寫它的英文名稱，後面接那一行的名字。
   - 數字：「Trust 到達 70 時」。
   - 文字變數裡的某一行：「Shop 的店租逾期時」。
3. **用回覆序號做定期事件與隨機事件**：在作品設定或章節私設寫一張表，照回覆序號的個位數查。序號放在 Scene 第一行時寫「Scene 的回覆序號」，獨立成變數時寫「Turn」。
   ```
   Scene 的回覆序號，個位數：
   0：來一位第一次出現的人
   5：推出限時活動
   其他：照常
   ```
   抽任務、抽狀態也用同一個做法，表裡每個數字對一個結果。
4. **名稱改了、變數增減了，引用它的地方全部一起改**：更新那一句的名稱列表、狀態面板、作品設定、章節、別的變數的說明。
5. 作品設定的更新指示用「接上作品設定、狀態面板與測試」那一句（官方配方的 `[[var:…]]` 格式這裡換成那一句）。

## 一個變數的說明怎麼寫
說明是模型更新這個變數時唯一的依據，也是使用者在 Studio 裡要回頭讀的東西。固定寫成下面的順序，就這幾段：
1. **【用途】** 一句話：這個變數記什麼。
2. **【樣子】** 先講幾行與換行的寫法，接著直接放整個變數的版型，一行一行照實際的樣子排，emoji 只出現在這裡。玩家自己決定的欄位用欄位名（店名、暱稱），模型看到具體例子會照抄。
3. **【每一行】** 有序列表，第 N 項對應版型的第 N 行。每一項把這一行的「放什麼、能填哪些值、什麼時候改」寫在一起，最多三句。格式和更新寫在同一項裡。
4. **跨行的規則塊**：只有一套規則同時管好幾行、或管整個變數時才另開一塊（例如【好感】【階段】【揭露】【收入與結算】），每塊用有序列表，一個變數最多四塊。

寫的時候守這幾條：
1. 列點一律用有序列表。
2. 例子只放在不看例子就會寫錯的那一行，用「例：「…」」接在該項後面；其他行靠版型就夠。
3. 預設值本身就是「未設定」，玩家說了模型自然會填，說明從用途直接寫起。
4. 有序列表的序號就是行號，直接寫內容。
5. 規則直接寫在這個變數的說明裡，更新時模型讀的就是這一段。
6. 狀態面板靠固定順序與全形寬度截取的那一行，欄位清單寫死，模型每次照同一份清單填。
7. 只有一種開局時，初始值就是變數的預設值；有多種開局時，預設值放最常用的那個，其他開局的差異寫在開局章節的私設。預設值只在新聊天套用，舊對話不會重設。
8. 多行文字變數的【樣子】寫「用真正的換行分隔，不要使用\ n」，反斜線與 n 中間有空格。這句是防模型寫出字面的換行符號，整理時保留。
9. 格子變數只在第一格寫完整，其他格寫「樣子和所有規則都和第一格一樣」。
10. 不重抄角色卡已經寫的階段行為，只寫卡裡沒有的。

**範例（虛構，改寫前後）**
改寫前，每一行都是一長句，同一行的規則還拆在【格式】和【更新】兩處：
```
第3行：🏠 店租：寫月租金額與繳款日，並註明目前是已繳還是逾期，例如「🏠 店租：18,000 元｜每月 5 日｜已繳」。
…
【更新】
- 店租過了繳款日還沒繳就改成逾期，付清後改回已繳。
```
改寫後：
```
名稱 Shop｜文字
【用途】{{user}} 這間店的錢、食材、店租，和答應了還沒做完的事。
【樣子】固定四行，用真正的換行分隔，不要使用\ n：
💰 現金 N 元｜今日營收 N 元
🥬 食材：…
🏠 店租：月租 N 元｜每月 D 日繳｜繳款狀態
📌 約定：…
【每一行】
1. 都寫目前的總值。客人結帳時加進現金和今日營收，進貨、繳租時從現金扣。日期換到隔天時今日營收歸零。
2. 只寫快用完和已經用完的食材，用「、」隔開，都夠時寫「充足」。用掉最後一份時寫進來，進貨後拿掉。
3. 繳款狀態寫「剩 N 天」或「逾期」。日期每換一天把 N 減 1；到 0 時還沒付就改成逾期；付清時改回「剩 30 天」。
4. 一筆寫成「對象：內容（期限）」，用「；」隔開，最多五筆，沒有時寫「無」。例：「房東：補繳店租（3月12日）」。答應時加上，完成、取消或過期時刪掉。
```

## 數字變數、好感與關係階段
**數字變數的說明**
1. 說明寫兩塊：【用途】一句；【規則】用有序列表寫什麼事件加減多少、單則上限。
2. 範圍說明用有序列表，一個區間一項，寫這個區間裡他對 {{user}} 的感受與傾向。留白的話只有數字在動，態度不會變。
3. 最小值、最大值、起始值填在各自的欄位。

範例（虛構）：
```
名稱 Trust｜數字｜最小 0｜最大 100｜起始 10
說明：
【用途】{{char1}} 對 {{user}} 的信任。
【規則】
1. 他在場時每則檢查：{{user}} 守住答應的事 +2；替他擋下麻煩 +4；說謊被他發現 -6。
2. 一則回覆合計最多 +4、-6，同一個理由只算一次。
範圍說明：
1. 0～29：對 {{user}} 還有戒心，只想把該談的事談完。
2. 30～69：覺得 {{user}} 可以相處，會想多留一會。
3. 70～100：把 {{user}} 當成自己人，遇到事情會先想到 {{user}}。
```

**好感與關係階段**
1. **好感**寫什麼事會加、什麼事會減，各給一個固定的量，並設一則回覆的加減上限。對方在場時才檢查。好漲還是難漲照角色的性格與經歷定，寫在角色卡；單則上限只防數字暴衝，不拿來做難度。
2. **好感區間寫成心境**。✕「80 以上戀人」→ ○「80 以上是愛上了」。區間寫成關係，數字一到模型就自動確認。作品設定配上「關係怎麼確認」那一句。
3. **好感高代表在意，不代表他會把事情說出來**。他知道什麼、什麼條件才說，照角色卡的「認知範圍」。
4. **關係階段需要才設**，另立一行。用看得見的事實命名（「還沒認定」「認定之後」），和角色卡「與 {{user}}」底下的小節用同一個名字，模型靠這一行知道現在演哪一面。它記的是目前的關係，不是劇情的進度：判定寫一件看得見的事，一次最多變一階，不排成一串步驟。
5. 階段可以寫成「階段（他的心意）」：括號是參考，改括號不算升階。單方面的暗戀、債務這類關係寫在括號裡；爭執暫時疏遠時維持原階段，括號寫「保持距離」加心意，和好後改回。

## 整理既有的變數
使用者已經做好的變數都留著，要刪、要合併先問他。
1. 讀全部的變數和狀態面板。
2. 每個變數對三件事：它是「先分三種」的哪一種、類型選得對不對、規則是不是一則回覆做得到。
3. **計算分兩種看，變數都留著**：算一步的留著，補上「把算式和結果寫出來」；回頭數天數、歸零進位、取餘數、連續好幾步的列進下一步。
4. 要改寫的計算，以及想刪、想合併、想改類型、想改名稱的，一項一項列給使用者：是哪個變數、為什麼、改成什麼樣子，由他決定。改不成一則回覆做得到的規則也列在這裡。
5. 使用者同意後才動；他把變數這一塊交給你時直接整理，做完照第 4 步的格式回報。改了名稱就照「怎麼引用」把引用的地方一起改；行數改了就回頭檢查面板那一格。

## 接上作品設定、狀態面板與測試
變數寫完還有三件事，照順序做：
1. **作品設定放一句更新總則**。官方說明寫作品設定裡要有更新指示，AI 才會正確更新變數，所以在作品設定的「變數」一節放這一句：「每則回覆結尾更新（這部作品全部的變數名稱，用頓號隔開），照各自的說明寫目前的總值。」例如「每則回覆結尾更新 Scene、Trust、Shop，照各自的說明寫目前的總值。」細則留在各變數的說明，作品設定只放這一句。
2. **狀態面板對應每個變數**：
   - 給玩家看的變數各放一格。
   - 變數的行數改了，回頭檢查那一格會不會超過 300px。
3. **請使用者用便宜的模型開新對話測十則**（我沒辦法自己開聊天室），請他看五件事：格式有沒有跑掉、序號有沒有每則加一、數字有沒有照規則動、新角色有沒有出來、同一個暱稱前後有沒有一致。

## 官方限制
1. 變數在「章節」步驟建立。整部作品最多 10 個。數值由 AI 依對話內容自動更新。
2. 類型有數字、文字、布林值、列舉；畫面只能選文字與數字，布林與列舉只有用 MCP 建立才能指定，畫面上是灰色。這套工作流只用數字與文字。
3. 上限：名稱 10 字、不含空格；說明 5,000 字；範圍說明 5,000 字；起始值 200 字。四者都計入作品總字數 30,000。
4. 數字變數可設最小值、最大值與範圍說明；文字變數的範圍說明留空。需要負值時（欠費、赤字）把 `min_value` 改成負數。
5. 文字變數的值可以用換行與條列顯示。
6. 官方配方：日期時間、地點、事件摘要三個文字變數放進狀態面板。
7. 值沒顯示時：狀態面板原樣出現 `{{名稱}}` = 沒有該名稱的變數，檢查名稱；顯示「—」= 值是空的，在作品設定補更新指示；下半被裁切 = 高度超過 300px。
8. MCP 的指南對變數只說「選用，第一版通常 0～2 個」，沒有教怎麼寫，官方細節以 Studio 的說明頁為準。

## 自查
1. 規則裡有沒有回頭數已經過了幾天、歸零進位、取餘數、連續好幾步的算式？有就改成記「剩幾天」、累計值加等級表，或拆成一步一行。一則回覆要算的地方有沒有超過兩三處？
2. 整理時變數有沒有被順手刪掉或併掉？作者寫的計算有沒有沒問就改掉？
3. 好感區間有沒有寫成關係（戀人、情侶）？有就改成心境。
4. 玩家不需要知道的變數有沒有被放進狀態面板？
5. 改過名稱的變數，引用它的地方有沒有一起改？更新那一句列的名稱，和實際的變數一致嗎？
6. 新作品有沒有先替作者找過候選？作品的核心和角色自己的生活這兩類有沒有看過？
