# 開場、起手式、範例對話、標題標語、介紹頁
> 格式與欄位是官方規則，寫法是這套工作流的做法。

# 開場

## 格式：不照做會壞掉的規則（官方）
- **沒有名稱的行會被當成動作描寫**；有「名稱: 」的行是該角色的對話框。聊天不支援 Markdown。
- 名稱必須與角色設定裡登錄的完全一致，冒號後空一格。用 `{{charN}}` 或登錄名稱都可以，要和角色順序對得上。
- 動作描寫用星號包住，另起一行，句尾要有句號。動作描寫裡出現冒號會被誤認成名稱。
- 會壞掉的寫法：
  - `徐俊: *笑著* 嗨` → `*笑著*` 會消失；動作移到上一行。
  - `**徐俊**: 嗨` → 不會被辨識為名稱；寫 `徐俊: 嗨`。
  - `*徐俊環顧房間*`（缺句號）→ 動作描寫變成台詞；寫 `*徐俊環顧房間。*`。
- 不寫沒有說話者的引號台詞。
- 開場不會自動套用星號，畫面看起來正常也不一定格式正確，寫完照上面幾條對一次。
- 名稱含「（暫名）」之類的字樣時，標籤也會帶著，發布前先改成正式名稱。
- 基本格式：
```
*徐俊尷尬地笑了。*
徐俊: 今天遲到了呢。
```

## 欄位（官方）
- 一部作品 1～5 個開場（`story.openings`），每個有 `id`、`originId`、選填的 `title`（20 字內，留空會顯示「開場 N」）、`body`（20,000 字內）、自己的 `chatStarters`（0～3 個，各 200 字內）。陣列的第一個是預設。
- 內容預算只算最長的那個開場加它的起手式。官方建議 700～1,200 字，越長玩家越容易在第一個畫面就離開。
- 後面的開場可以是空字串（自由開始），保留不要補招呼語。
- 編輯時保留既有的 `id` 與 `originId`，工具用法與鏡像欄位見 `tools.md`。Cinema 的開場格式見 `platform.md`。
- **屬於公開區域**，進入作品前也可能看到。安全作品與成人作品都照公開標準寫（`safety-and-rating.md` 第一節「這套工作流的做法」）。開場不能放秘密圖片或成人圖片。

## 開場與章節的綁定
- 第一個開場固定綁在第一個章節，其他開場可以各自選要綁哪一章。綁定的欄位、怎麼排開局章節在 `variables-and-episodes.md` 的「章節」。
- 改開場時，`startEpisodeId`、`unlock`、`imageId` 三個欄位原樣保留；要改綁定請使用者在 Studio 做。

## 寫法
照 `writing-rules.md` 第二組和 `style.md` 的「活場接龍」寫，這裡只列開場特有的事。官方指南建議的固定結構（幾句旁白接一句台詞再接旁白）和「從緊繃的時刻切入」不用照。
- **寫正在發生的場景**，不寫劇情摘要、設定說明或自我介紹。不在開場揭開核心的秘密。
- **結尾照玩家會動手的順序排**現場等著他處理的東西，不用玩家的台詞收尾。

**開場是模型唯一會照著學的示範**（範例對話預設不放），它長什麼樣，模型就寫成什麼樣：
- **文體就是開場的文體**。要小說體就用完整的句子寫；開場裡三五個字就一個逗號，模型的回覆也會碎。
- **輸出格式在開場裡完全照規則演一次**。規則把私訊、語音獨立出來，開場就不能還放在別的區塊裡。改了格式規則之後，開場要重對一次。
- **角色的態度要對得上設定**。設定寫他一開始有戒心，開場就不能已經在疼玩家。
- **名字和暱稱會被照抄**。路人不用類型當名字（守護某某、黑粉幾號），模型會學成每個人都這樣取。
- **隨機角色的作品，開場不放有名字的固定角色**，不然每一場都遇到同一批人。用匿名的帳號或未讀通知，讓模型第一則回覆才生成。
- **具體的行為、食物、飲料、小動作只放這場戲真的需要的**，模型會反覆拿來用。

## 起手式
每個開場有自己的起手式，0～3 個，各 200 字內，看情況放。要放就寫玩家具體的行動或試探，不寫「開始」「對話」「聽他說明」這類抽象選項。刻意留空的保持空，不借用別的開場的。

# 範例對話
- **預設不放**。裡面出現的行為、食物、飲料，模型會在之後的回覆一直拿來用。聲口與格式靠開場示範，公開時沒有範例對話也可以。
- **有特殊輸出格式的作品也一樣**（平台畫面、彈幕、系統視窗）。把版型直接排在角色卡或作品設定裡，連程式碼區塊的框一起排出來，每一種行各一行；格式寫對了，範例對話就可以拿掉。
- 使用者明說要時才寫：最多 5 個，每個 5,000 字。格式是旁白 `*…*`、台詞 `{{char1}}: …`。每個範例只放一種模式，用場景呈現語氣，不放 `{{user}}:` 台詞行。`{{char1}}` 的編號跟著角色順序，調序後要檢查。

# 推薦角色模板（選填）
- 最多 3 個，是建議玩家開始聊天時可以選的身分（玩家自己建立，作者只是建議）。工作區欄位 `templatePersonas`。
- 玩家的職業或關係必須先確定才能推進，或作品分成幾條路線、每個身分有不同關係時才需要。不需要就留白。

# 標題與標語
- 標題 20 字；標語 100 字，是玩家在列表看到的一句話。兩個欄位 AI 都會讀。
- **標語寫目前的情況，不寫劇情摘要**：✕「普通上班族調到新部門後經歷的故事」→ ○「第一天上班，坐在隔壁的人竟是前任。」

# 介紹頁
介紹頁（`introMd`、`introHtml`）是給玩家看的，AI 不會讀，不計入 30,000 字。它只有一個工作：讓玩家想進來玩。

**不把設定和開場複製貼上。** 介紹頁不是設定摘要，也不是把作品設定、角色卡、章節、開場換個排版再講一遍。每一句都要為介紹頁重新寫。

## 寫什麼
1. **先找到主題**：玩家在這部作品裡的處境與關係，一句話：{{user}} 是誰，跟誰，卡在什麼處境，被什麼拉著往下走。把專有名詞、數值、機制全部拿掉，這句話還成立才是主題。標語、第一個開場、使用者自己怎麼形容這部作品，三者指向的同一件事就是它。有兩個以上候選時問使用者，不全部都寫。
2. **只拿玩家需要的**：
   - 決定要不要進來所需要的：我是誰、對面是誰、氣氛是什麼。
   - 一進去就會碰到的兩三條規則、可以做的事。
   - 操作上要知道的：狀態面板怎麼看、要不要先填玩家模板，寫短。
   - 可以去的地方、可以選的玩法，做成一眼看完的卡片或標籤，一項一個詞或一句話。
3. **角色只給看得到的樣子**，兩三句，每個角色篇幅差不多。寫看得見的事，不寫背後的原因：✕「其實他是為了贖罪才留下來」→ ○「他每天最早起，最晚睡，沒有人見過他吃配給。」
4. **材料不夠時補一小段氣氛**，不補設定。這一小段另外寫，不從開場剪貼。

## 不放的東西
- 作品設定、角色私設、章節裡的句子與內容：經歷、動機、真相、揭露時機、對 {{user}} 的真實態度。
- 變數、數值、好感規則、隨機表、難度的內部數字。
- 寫給模型的規則句（「角色將依照…」「當 {{user}}…時則…」）、變數名、欄位名。
- 開場的原文。
- 玩家做選擇用不到的世界觀：歷史、制度細節。

## 怎麼寫
- **用處境講，不用規格講**。✕「本作設有信任度系統，數值 0～100，達 60 可進入內區」→ ○「他們讓你睡在門邊。想往裡面走，得先讓人願意替你開口。」
- **讓世界裡的聲音對玩家說話**（平台、招募方、管理員、旁白），一個區塊一兩句，講到玩家懂了就停。
- **提到玩家時用 {{user}}**，介紹頁會把它換成玩家的名字。
- **鉤子只留在結尾**：整頁最後用一句反問或邀請收，只點到，不接著解釋。前面各區塊直接講清楚。
- **主詞清楚**：誰付錢、誰動手、誰承受，要讀得出來。
- **自創的詞第一次出現時說出它實際是什麼**。
- **用詞和遊戲裡一致**，同一個東西只有一個名字。不用作者的行話（「內建的品項」「已有設定」），改成玩家拿得到的東西。
- **同一件事只講一次**，寧短不湊。

## 介紹頁的固定做法
- 使用者改過的介紹文字是口吻的基準。幫忙看的時候只挑主詞、名詞落地、用詞一致、行話這幾類問題，逐處列出原句與建議，等使用者說改再改，不整段重寫。
- 不放角色秘密與劇情轉折。可公開：預設身分、地圖、玩家看得到的規則、日常活動時間。
- 玩家模板用「選項列表」格式（A／B／C）加一筆範例。
- 角色標籤：公開特徵加網路梗，劇透程度高的每人最多一個。
- 不用 emoji 圖示，顏色標示就夠。

## 自查
- 有沒有哪一句是從作品設定、角色私設、章節或開場搬過來的？有就重寫或刪掉。
- 遮住標題，十秒內說得出這部作品在玩什麼嗎？說出來的是處境，還是一串設定？
- 有沒有數值、變數名、條件句？有沒有把想留給玩家發現的事先講了？
- 同一件事有沒有出現兩次？
- 鉤子是不是只在結尾？

## 做 HTML 介紹頁時才看（官方規則）
- 公開前至少 100 字。Markdown 與 HTML 兩種模式各上限 50,000 字。
- `<style>` 標籤不會生效，一律在標籤上直接寫 `style="…"`；`@media` 不能用，響應式用 `flex-wrap`。不用 JS、iframe、表單、按鈕、外部 CSS、SVG。
- 能用的標籤：`section`、`article`、`div`、`h2`～`h4`、`p`、`ul`、`li`、`blockquote`、`details`、`summary`、`figure`、`img`、`span`、`strong`、`em`。替換標記：`{{char1}}`、`{{user}}`、`{{creator}}`、`{{story}}`。
- 圖片用 Tikita 的公開網址，`class="intro-html-img"`，有 `alt` 與明確的 `width`／`height`。外部圖片網址貼上後按「匯入」會搬到 Tikita，不合分級或損毀的不會搬，匯入後檢查。有中日韓文字的封面先生無字底圖，文字另外排版。
- 版面：行動版優先，約 390px 寬檢查。單一色調加一個強調色。不大卡套大卡，用全寬區塊、細分隔線、精簡的頭像列（80～100px）。避免大型表格與長條列。
- 字級：標籤 12～13px、內文 14～16px、段落標題 20～28px，行高約 1.65～1.8。
- 順序：玩家是誰 → 情境的規則 → 角色卡 → 可以做的選擇 → 一小段氣氛 → 結尾留一個鉤子指向第一場戲。有圖就讓每張圖各有作用，不連續重複同一張。
