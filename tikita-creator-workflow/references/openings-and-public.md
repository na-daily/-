# 開場、起手式、範例對話、標題標語
> 格式與欄位是官方規則，寫法是這套工作流的做法。

# 開場

## 格式：照做才會正常顯示的規則（官方）
- **沒有名稱的行會被當成動作描寫**；有「名稱: 」的行是該角色的對話框。聊天不支援 Markdown。
- 名稱必須與角色設定裡登錄的完全一致，冒號後空一格。用 `{{charN}}` 或登錄名稱都可以，要和角色順序對得上。
- 動作描寫用星號包住，另起一行，句尾要有句號。動作描寫裡出現冒號會被誤認成名稱。
- 會壞掉的寫法：
  - `徐俊: *笑著* 嗨` → `*笑著*` 會消失；動作移到上一行。
  - `**徐俊**: 嗨` → 不會被辨識為名稱；寫 `徐俊: 嗨`。
  - `*徐俊環顧房間*`（缺句號）→ 動作描寫變成台詞；寫 `*徐俊環顧房間。*`。
- 每一句台詞都掛在一個名稱底下。
- 開場不會自動套用星號，畫面看起來正常也不一定格式正確，寫完照上面幾條對一次。
- 名稱含「（暫名）」之類的字樣時，標籤也會帶著，發布前先改成正式名稱。
- 基本格式：
```
*徐俊尷尬地笑了。*
徐俊: 今天遲到了呢。
```

## 欄位（官方）
- 一部作品 1～5 個開場（`story.openings`），每個有 `id`、`originId`、選填的 `title`（20 字內，留空會顯示「開場 N」）、`body`（20,000 字內）、自己的 `chatStarters`（0～3 個，各 200 字內）。陣列的第一個是預設。
- 內容預算只算最長的那個開場加它的起手式。官方建議 700～1,200 字，越長玩家越容易在第一個畫面就離開。
- 後面的開場可以是空字串（自由開始），照原樣留空。
- **屬於公開區域**，進入作品前也可能看到。安全作品與成人作品都照公開標準寫。開場的圖片只用公開的、安全分級的圖。

## 寫法
這裡只列開場特有的事。官方指南建議的固定結構（幾句旁白接一句台詞再接旁白）和「從緊繃的時刻切入」只當參考。
- **寫正在發生的場景**。核心的秘密留到後面揭開。

**開場是模型唯一會照著學的示範**，它長什麼樣，模型就寫成什麼樣：
- **文體、長度與密度就是開場的樣子**。要小說體就用完整的句子寫；開場裡三五個字就一個逗號，模型的回覆也會碎。要模型寫到多細，開場本身就寫到那個密度。
- **輸出格式在開場裡完全照規則演一次**。規則把私訊、語音獨立出來，開場裡的私訊、語音也獨立出來。改了格式規則之後，開場要重對一次。
- **角色的態度要對得上設定**。設定寫他一開始有戒心，開場裡的他就帶著戒心。
- **名字和暱稱會被照抄**。路人取像真人會用的名字；拿類型當名字（守護某某、黑粉幾號），模型會學成每個人都這樣取。
- **隨機角色的作品，開場用匿名的帳號或未讀通知帶出人**，讓模型第一則回覆才生成。開場裡有名字的人，每一場都會出現。
- **具體的行為、食物、飲料、小動作只放這場戲真的需要的**，模型會反覆拿來用。

## 起手式
每個開場有自己的起手式，0～3 個，各 200 字內，看情況放。要放就寫玩家具體的行動或試探。刻意留空的保持空。

# 範例對話
- **預設留空**。裡面出現的行為、食物、飲料，模型會在之後的回覆一直拿來用。聲口與格式靠開場示範，公開時沒有範例對話也可以。
- **有特殊回覆格式的作品也一樣**（平台畫面、彈幕、系統視窗）：版型寫在敘事指示或角色卡之後，範例對話就可以拿掉。
- 使用者明說要時才寫：最多 5 個，每個 5,000 字。格式是旁白 `*…*`、台詞 `{{char1}}: …`。每個範例只放一種模式，用場景呈現語氣，只放旁白與角色的台詞。`{{char1}}` 的編號跟著角色順序，調序後要檢查。

# 推薦角色模板（選填）
- 最多 3 個，是建議玩家開始聊天時可以選的身分（玩家自己建立，作者只是建議）。工作區欄位 `templatePersonas`。
- 玩家的職業或關係必須先確定才能推進，或作品分成幾條路線、每個身分有不同關係時才需要。不需要就留白。

# 標題與標語
- 標題 20 字；標語 100 字（官方建議約 20～80 字），是玩家在列表看到的一句話。兩個欄位 AI 都會讀。
- 官方補充：標題短、好記、情緒具體，常見型是帶張力的情境、矛盾、身分加鉤子、把地點當承諾。
- **標語寫目前的情況**：✕「普通上班族調到新部門後經歷的故事」→ ○「第一天上班，坐在隔壁的人竟是前任。」
