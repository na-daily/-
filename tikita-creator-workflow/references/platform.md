# 平台規則：上限、必填、發布、官方指南
> 官方規則。數字以 `workspace_get_content_budget` 與工具報錯為準。

# 欄位上限與作品字數 30,000 字

## 哪些欄位計入 30,000 字

| 欄位 | 上限 | 數量 | 計入 |
|---|---|---|---|
| 標題 | 20 字 | 1 | 否 |
| 標語 | 100 字 | 1 | 否 |
| 作品設定（detailMd） | 20,000 字 | 1 | 是 |
| 角色名稱 | 15 字 | 最多 10 個角色 | 是 |
| 角色公開卡 | 20,000 字 | 每個角色 | 是 |
| 角色 `secret` | 20,000 字 | 每個角色 | 是 |
| 開場 | 每個 20,000 字 | 1～5 個 | 是，只算最長的那一個 |
| 起手式 | 每個 200 字 | 每個開場 0～3 個 | 是，只算最長那個開場的起手式 |
| 範例對話 | 5,000 字 | 最多 5 | 是 |
| 變數 | 名稱 10、說明 5,000、範圍 5,000、初始值 200 字 | 最多 10 | 是 |
| 章節標題・切換條件 | 20 字・200 字 | 每個章節 | 是 |
| 圖片群組名稱・圖片說明 | 50 字・100 字 | 群組 50、圖片 500 | 是 |
| 章節內文 | 2,000 字 | 每章，最多 20 章 | **否** |
| 章節私設 | 2,000 字 | 每章 | **否** |
| 設定集 | 每則 500 字 | 每部 200 則 | **否** |
| 介紹頁 | 50,000 字 | 1 | **否** |
| 創作者留言（creatorNotes） | 20,000 字 | 1 | **否** |

- **介紹頁與創作者留言，AI 不會讀。** 對話不會反映在這兩處寫的設定，只給玩家看。不要把設定、規則、矩陣寫在這裡。
- 公開卡 AI 也會讀，所以要用設定填滿；想藏的放 `secret`。
- 角色最多 10 個，台詞用 `{{char1}}`～`{{char10}}` 依角色順序編號，順序變動編號就跟著變。
- 作品字數可在製作畫面底部按 ⓘ，從最大的項目開始看，通常是角色。

## 設定滿出來時，由上往下試
1. 可以藏的資訊放 `secret`。公開卡只留六樣。
2. 共通設定（世界觀規則、組織、地名、稱呼規則）只在作品設定寫一次；角色欄只寫這個人物不同的地方。
3. 偶爾才出現的設定（地名、組織、道具、過去事件）放設定集，只在關鍵字出現時才送入，且不計入字數。
4. 要鎖定的階段內容、功能區塊、一次性的關卡或事件放章節私設（章節內文與私設每章各 2,000 字，不計入合計）；一般前後反差放角色卡「與 {{user}}」小節。
5. 語氣靠開場直接演出來，不在角色卡寫長篇規則（官方舊說明建議放範例對話，這套工作流預設不放）。
6. 刪掉重複的指示。目標不是把欄位填滿，越長重要指示越容易被埋掉。

**矛盾的指示要收成一種性格**，不要散在三個欄位互相打架（例如作品設定寫「不表露情緒」、公開卡寫「表情豐富」、`secret` 寫「全寫在臉上」，AI 每次回答會挑不同的一邊，看起來像設定被無視）。改成同一個欄位一句：「想藏住情緒，卻會寫在臉上，本人以為自己藏得很好」。

角色一直無視設定時，問題常常不是篇幅，先檢查同一條規則是不是寫在多處、是否互相矛盾。

# 發布
## 發布條件（缺任何一項，公開按鈕都會被擋）
章節與範例對話都不是必要的：使用者實際公開過沒有章節、沒有範例對話的作品。官方舊說明寫「至少 1 個有內文的章節」，已經不適用。
| 步驟 | 需要 |
|---|---|
| 個人資料 | 標題、標語 |
| 個人資料 | 至少 1 名角色：名稱、介紹、**個人資料圖片（頭像）** |
| 對話 | 開場 |
| 圖庫 | 至少 1 張圖庫圖片、縮圖 |
| 公開設定 | 至少 1 個分類、至少 1 個標籤 |
| 公開設定 | 介紹頁至少 100 字 |
| 公開設定 | 測試對話 10 次 |
| 公開設定 | 標示二次創作時，要填原作標題 |
| 全部 | 作品字數 30,000 字以內（超過連儲存都會被擋） |
- 起手式不是必填，0 到 3 個，看情況放（官方建議填滿 3 個，不強求）。
- 角色頭像與縮圖都需要圖庫圖片，文字草稿完成後還要處理圖片；有 `asset_*` 工具可上傳或匯入。

## 測試對話 10 次
- 公開前要親自和自己的作品對話 10 則，同一間聊天室傳 10 次即可，不必另開新聊天室；自動出現的開場不計次數。
- 看不到聊天按鈕時，卡片上會有「草稿」標籤：先按編輯畫面下方的「建立作品」（以不公開狀態完成建立，不是公開），之後聊天按鈕就會出現。「不公開・編輯中」只代表已儲存、還沒按建立作品，聊天仍可進行。
- 自己的作品用基本模型時，前 10 次免費。
- MCP 只能改草稿，這一步要請使用者在 Studio 自己做。

## 分類、標籤、創作者留言
- 分類最多 3 個；標籤 1～15 個，用 MCP 建立新作品時至少 6 個。
- **創作者留言**：最多 20,000 字，玩家看得到、也會被審查（標準與介紹相同）；AI 不會讀，不計入字數。不是寫設定的地方，只放狀態面板用法、可重新回覆之類的簡短說明。
- 二次創作：勾選後原作標題必填，作品固定全年齡並排除收益結算，儲存後無法自行取消，要向客服申請。

## 公開範圍與關聯作品
| 設定 | 誰看得到 |
|---|---|
| 公開 | 所有人，出現在列表與搜尋 |
| 連結公開 | 只有知道網址的人，不在列表 |
| 不公開 | 新使用者看不到；已在對話的人可繼續使用，紀錄保留 |
- 第一次公開的時間會反映在新作與急上升，不要先公開再收回，準備好再第一次公開。
- 暫時下架：設不公開，隨時可再公開。只給部分人看：連結公開。徹底下架：刪除，無法復原。
- 不公開不會擋住既有使用者；若有人被擋，是營運審查限制，應已收到通知。
- 關聯作品：可把同世界觀的多部作品連起來；成人驗證視窗只顯示全年齡作品，但連結對象可以加入成人作品。
- 公開後修改，儲存後立刻生效（建立畫面改完還要按儲存，只編輯就離開不會生效）。進行中的聊天室可能感覺不到變化，因為 AI 會參考累積的對話，請用新聊天室確認。

# 官方 MCP 指南摘要
官方指南裡關於寫作風格的軟性建議（開場寫 `{{user}}`、從緊繃時刻切入、必寫 3 個以上主線章節、必放 2～5 則範例對話）是給從零呼叫 `story_create_draft` 的一般使用者的，這套工作流不照；這裡只留基調原則、角色數量、分類、欄位與 ID、Cinema、預設值與審查草稿的原則。

MCP 只提供一份創作指南（`https://mcp.tikita.ai/guides/story-creation.md`）和一份分類表（`https://mcp.tikita.ai/guides/categories.json`）。

## 基本原則
- 主題、類型、配對、基調由創作者決定，不因為流行而改。創作者沒給前提就先問，除非他明說交給你。
- 性別、配對、年齡帶、分級、關係方向沒指定但寫作必須用到時先問；不問也能寫，就用中性寫法與 `gender: "unset"`。
- 嚴守基調：平靜的作品不為製造賭注而升級成綁架、謀殺、犯罪。用重複的物件、沒寄出的訊息、舊約定、延遲的道歉、缺失的記憶這類軟壓力。
- 只描述設定、對角色扮演沒幫助的欄位，縮短或改寫成可玩的規則。

## 角色數量參考
- 專注的關係、懸疑、日常、親密劇用 1 位主角；校園、群像、實境秀、團隊用 3～6 位；7～9 位只用在每個角色定位都不同的動作或開放沙盒。
- 章節依這套工作流只做用得到的；只有使用者明確要求直接呼叫 `story_create_draft` 新建草稿時，才受該工具 schema 下限（至少 3 個章節、2 則範例對話、6 個標籤、主開場 500 字）限制。

## 標題與標語
官方補充：標題短、好記、情緒具體，常見型是帶張力的情境、矛盾、身分加鉤子、把地點當承諾；標語約 20～80 字。

## 欄位與 ID 注意事項（官方）
- 每個角色都要有 `character_intro` 與 `secret`，不能留空；有用的 `secret` 會改變行為與後續場景。
- `world`：MCP schema 裡指可玩的現實（最多 4,000 字）；Studio 編輯畫面沒有獨立的這個欄位，世界觀統一寫進 `detailMd`。
- 新增角色、章節、變數、對話、圖片連結時，id 由伺服器指派 `ws_<uuid>`（圖片為 `ws_img_<uuid>`），不要自己編純 UUID 形狀的 id。
- 圖片：文字可以先完成，但可發布的草稿要規劃縮圖與角色頭像（以及視需要的場景圖、秘密圖）。

## Cinema（視覺小說）
- 建立：`story_create_draft` 的 `story.isCinema: true`；`primary_image_id` 維持 null，顯示圖來自 cinema 縮圖。
- 開場 `body` 必須是 JSON 字串 `{"version":1,"blocks":[…]}`，不是 Markdown，不是物件，也不是程式碼區塊。每個 block 要有非空 `id`。
- block 種類：`narration`（`text`）、`dialogue`（`name`、`text`，選填 `position` 為 left 或 right，選填 `userImageId`、`imageUrl`）、`image`（`userImageId` 加 `imageUrl`，選填 `caption`，必須指向已完成的自有圖庫資產）、`video`（僅佔位）。上限 64 個 block 與 20000 UTF-8 bytes；不適用 500 字下限。
- 縮圖：`cinema_set_thumbnails`（最多 6，第一張為主縮圖）。立繪：`cinema_set_character_sprites`（每個表情名稱唯一、要有自有圖庫圖片，第一個放中性預設表情，全作品最多 200 張）。角色 id 用 `workspace_get_draft` 的 `characters[].id`。
- 發布門檻：至少 1 張縮圖，且每個角色至少 1 張立繪；用 `cinema_get_publish_gate_status` 確認。套用與發布都要使用者在 Studio 存檔。

## 預設值
`originalLanguage` 預設 `ko`（依作品實際語言填，例如 `zh-TW`）、`episodeMode` 預設 `sequential`（有章節時改成 `free`，也就是自由移動）、`chatImageMode` 預設 `background`、`variableViewMode` 預設 `default`、`monetizationMode` 原創作品用 `full`。同人作品才用 `none`，且必須填 `originalWorkTitle`（實際原作名稱，不可用新作品名替代）；該分類創作者事後無法還原。

## 寫入前的欄位檢查
這裡只對欄位：
- 分類用官方韓文顯示名稱且最多 3 個。
- 每個角色的 `name`、`character_intro`、`secret`、`gender`、`age`（或 null）齊全。
- 開場保留既有的 `id`／`originId`。
- 圖片：沒有印出簽名網址；上傳槽完成前不當圖庫圖片；多張圖有分組；縮圖與頭像用圖庫 id。

## 審查現有草稿
- 不整份重寫：找最弱的 3 處，局部修補（模糊的標語、開場改成進行中的場景、把 `world` 的設定傾倒轉成作品設定的運作規則、修正分類名稱）。
- 完成後回報：標題、狀態、分類與標籤、角色／章節／範例對話數量，以及還需要創作者確認的部分。不貼原始 MCP 回應，除非創作者要技術細節。

## 宿主的聊天紀錄
MCP 讀得到 Tikita 存好的草稿，讀不到當前對話工具（OpenCode、Claude、ChatGPT 等）的完整對話紀錄。創作者要「整段對話的 Markdown」時，說明這點；可以整理 MCP 實際回傳的 Tikita 內容並註明範圍，不用摘要冒充原文。
