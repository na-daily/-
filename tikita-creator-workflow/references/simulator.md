# 模擬器類作品
> 這套工作流的做法，非官方。

玩家會遇到很多對象、有金錢或資源要結算、角色在遊戲中才生成時才需要這一份。一般的單一角色或少數角色作品跳過這一份。

## 機制、數值、經濟
- 核心循環：玩家每個回合大致在做什麼、做完得到什麼。每一項都要接得到變數，接不到的活動只當氣氛。
- 只追蹤會變的值，每個值只在當下看得到的事件更新。
- 成長用累計值加一張等級表：每件事加一個寫死的數（「完成同級任務 +2、高一級 +3、低一級 +1」），累計值只加不歸零，等級照表寫（「累計 10 是 2 級、25 是 3 級、45 是 4 級」）。同一個理由不重複計分，單則回覆設增減上限。
- 餘額可以是負數，代表欠費，下一期先追繳；數字變數的最小值要改成負數。
- 等級與權限用表格：每一級解鎖什麼、限制什麼。
- 難度是遊戲外的設定，角色不知道也不會問玩家。沒指定走預設，玩家明說才用另一個。初始值只在新聊天的第一則回覆校準一次。
- 外部（例如別的模型）提的漏洞，先看修正會不會讓規則變複雜，用最小的改法補，或判斷不值得補。

## 對象格、名冊與隱藏底細
1. **主要格與名冊**：會反覆出現、有好感路線的進主要格（多行，一格一人）；其他人記在一個名冊變數，一人一行。
2. 主要格的欄位分兩種：固定欄位登場時一次生成，之後照抄；會變的欄位（階段、好感、當下動作、心聲）每則更新。
3. **要等條件才揭露的欄位**：在對象進主要格的同一則，就把完整的內容寫進隱藏變數，主要格先寫「？？？」；條件達成時從隱藏變數原樣抄過來，並在隱藏變數那一行標「（已揭露）」。揭露條件用有序列表，一項一個欄位。
4. **握有**：隱藏底細每人加一行，記他手上關於玩家的東西（住址、真名、錄下的檔案、借據）。這一行會變，拿到或失去時改寫；他拿來開條件時照這一行寫。
5. **格子滿了**：新對象先記在名冊；只有玩家用 OOC 指定「誰換成誰」才替換。換下來的壓縮成名冊的一行，行尾留階段與好感，換回來時照這行重建。進出的規則寫在主要格第一格的說明裡，名冊只留自己那一半。
6. 名冊設人數上限，超過時刪掉最久沒出現、關係最淺的一位。
7. **名冊的格式欄位只寫欄位名**：寫成「觀眾類型，例如榜一、黑粉」的話，模型會把類型當成名字用。
8. **讓既有角色讓出戲份**：規則寫明每場只讓名單裡的幾位出現，並要求每場有一位第一次出現的人做出讓人記得的事，新角色才推得出來。

## 數量在遊戲中才決定的實體
可領取 1～5 個的對象這一類。變數都要在開始前建好，兩種做法擇一：
1. **預留格**：一個數字變數 `Count` 加 N 個格子變數（沒用的預設「未領取」），狀態面板用 `{{#gte Count k}}` 決定顯示哪幾格。每個實體可有獨立卡片，但吃掉 N+1 個變數。
2. **單一清單變數**：一個文字變數，每個實體一行，上限寫在說明裡。只用 1 個變數，但狀態面板無法對每個實體做獨立進度條。

實體由模型依規則生成，屬於 NPC，不另建角色卡；領取條件與上限檢查寫進作品設定；生成規則放在生成當下會載入的地方（抽選或領取的那一章；沒有章節時放設定集）。

## 帳本與結算
1. 一行放目前持有與待結算，一行放今日收入；每個數字都寫總值。
2. 每筆收入在發生時加進待結算，寫原始金額。
3. 結算綁在絕對日期上（例如每月一號），日期到時結算一次：扣掉抽成（單一比例直接寫，級距多時列成分級表），剩下的加進總資產，待結算改寫成 0，並把算式寫在通知裡。固定扣款（月租、分期）也掛在某一次結算上。
4. 平台或系統以外收到的錢直接加進總資產；支出在實際付款時扣，可以扣到負數代表欠債。

## 動態角色：用一張通用卡加固定對話格式
適用：作品裡有一群由模型即時生成的角色（領取的對象、路人群、隊員、寵物等），數量、名字、外貌在遊戲中才決定。
1. **建一張通用角色卡**，代表「這一類角色」。`character_intro` 寫這類角色是什麼、資料從哪裡來；`secret` 分三塊：
   - 角色定位：這張卡代表誰；資料來源（對應變數的哪幾格、哪些資料取自其他角色卡的清單），不另行發明。
   - 輸出格式：每次開口或動作前一律標明是誰。固定寫法「名字（必要標籤）: 「…」」，標籤只放玩家需要一眼認出的資訊（例如分類 emoji、等級）。未命名時用固定替代名。多人同場各自分開、各自標名；動作描寫主詞寫清楚，不用「他／她」帶過。
   - 行為準則：態度怎麼隨變數（好感、狀態、階段）改變，說話風格怎麼區分個體，能力與外觀必須與資料一致。
2. **個體資料放變數**（照上面的「對象格、名冊與隱藏底細」），動態角色的資料都放在變數。
3. **格式的版型排在通用卡的「輸出格式」裡**，每一種行各排一行。
4. 其他角色卡裡若有此類角色的清單，欄位格式要跟通用卡讀取的欄位一致。
5. **原型與生成**：地點章節或作品設定寫原型（身分、癖好、性格、說話方式）；性別、名字、外貌在第一次見面時依配置生成，存進變數鎖定。通用卡的性別留空，頭像用標誌或剪影。
6. **介面型角色**（終端、系統、AI）同理建一張卡：把畫面版型（用程式碼區塊排的樣式與欄位）寫進卡裡。放設定集的話，關鍵字太窄會漏觸發、也容易跟作品設定重複。預設語氣與玩家可自訂的風格欄位（寫進介紹頁的玩家模板）都寫在卡上。設定集在這類作品可以是空的。
