# 動筆前必讀

寫任何會存進草稿的文字之前讀這一頁，寫完照最後的自查逐條對。這一頁是每一種設定都適用的規則；角色卡、世界觀、變數、正文各自的寫法在各自的檔案。

**規則是為了演出**。照做會讓角色的特性寫不出來時，以角色為準，回報時說明哪一條沒照做、為什麼。這四條每次都守：角色的反應寫到感受與傾向為止、每一句都是模型一則回覆做得到的事、常駐設定只寫方向、好感區間寫成心境。使用者的原稿和這四條衝突時，先問他要怎麼處理，再整理。

## 通用：每一種文字都適用
1. **讀者是負責扮演的模型**。每一句都在指揮它怎麼演。拿掉之後演出照舊的句子就刪。
   - **每一句都是模型在這一則回覆裡做得到的事**。模型只看得到現在這一則，所以時機綁在看得見的條件上：某個事件發生時、某個值到達哪一階或哪個數字時、切進哪一章時。「順著劇情自然發展」「視情況決定」「隨著相處慢慢…」「在適當時機」「遲早會曝光」這類句子，有條件可綁就改成條件，其餘整句刪。
2. **只寫有的事，用正面的說法**。規則寫成「要做什麼」，狀態寫成「現在是什麼樣子」。✕「並不…」「沒有…也沒有」「手邊沒有某樣東西」「還沒開口」。
   - **角色自己的事實照實寫，否定的也一樣**：他的底線、他拒絕做的事、他還沒知道的事、他避開的話題。
3. **每件事全作品只寫一處**。加規則前先查它已經寫在哪。同一個反應、同一個說法（「怕弄壞」「又氣又慌」）在各欄位之間只出現一次，別處換一個角度寫。
   - **往一個欄位加句子之前，先重讀那一整節**，已經講過的事併進原句。
4. **設定寫長期成立的事**，用現在的狀態寫。✕「爺爺上個月過世」→ ○「爺爺已經過世」。
5. **平台管的事交給平台**。全員成年、合意、禁止的題材由平台把關，設定裡只寫這部作品自己的內容。「不能強迫」「親密不拿來抵債」「不替 {{user}} 說話或做決定」「角色皆已成年」「雙方合意」這類防範句，看到就提出刪除。
6. **具體的東西留給模型當場生成**。設定寫他是什麼樣的人、會怎麼做。口頭禪原句、某道菜、某個小動作一寫進設定，模型每一則都會用。
   - **常駐設定寫方向與感受**。每一則都會送進模型的欄位，裡面清單上的每一樣模型都會每一則照用，所以清單只留給查表用的資料（價目、樓層、數值、抽選表），用短條列，一項一筆。
   - **角色的反應寫到感受與傾向為止**。感受（感到羞澀）和傾向（會想躲、會嘴硬）寫進設定；表現（耳根紅、別開視線）留給模型當場演。每一個寫到角色反應的欄位都一樣。
   - **態度分級寫每一級的人怎麼看 {{user}}**，做什麼留給模型演。✕「刁難、起鬨、試上限、嘲笑失誤、下指令」→ ○「把 {{user}} 當成笑料，只想看反應」。
7. **設定直白敘述，寫確定的事實**：發生過什麼、他是什麼樣的人、規則怎麼運作。抽象的詞換成它指的那件事（✕「背負著沉重的過去」），鉤子與懸念換成直接講（✕「似乎藏著…」「那一晚改變了一切」）。要鎖住的內容放進只在那一章才送入的地方。
8. **用字照作品的語言**。繁體中文作品用正字：嚮導、哨嚮。
9. **使用者給的修法只用在他指的那一處**，別的地方另外找符合那個場景的寫法。使用者說「抽象」「列資料」時，先弄清楚缺的是畫面還是心境，拿不準就問是哪幾處。
10. **結局和角色會變成什麼樣，留給玩家的行動決定**。設定只寫各方平常的態度，以及得知某件事之後會怎麼反應。
11. **寫進作品的文字，提到別處時用那裡的標題或名稱**。模型在對話裡讀到的是內容本身，所以指路要指到它讀得到的字：
    - 角色卡裡的小節：寫「{{char1}} 的「經歷」」「{{char2}} 的「認知範圍」」。
    - 世界與規則：寫那一節的標題，例如「「各項規則」的契約一節」。
    - 會變的值：寫它的英文名稱，例如「Trust 到達 70 時」「Shop 的店租逾期時」。
    - 章節：寫那一章的標題。
    - 「作品設定」「公開卡」「`secret`」「章節私設」「變數」「設定集」是這份 skill 和 Studio 的欄位名稱，用在這份 skill 和給使用者的回報裡。

## 文體：設定寫成條目，正文寫成流水句
模型會照著它讀到的句子寫，設定寫得零碎，它在聊天裡寫出來的正文也會跟著零碎，所以設定本身就用完整、連貫的句子寫。寫進草稿的文字分成兩種文體。

1. **設定用設定集條目體**：作品設定、角色卡、章節私設、設定集與變數說明，都像設定集或百科的條目那樣，以第三人稱陳述，名詞用精確的叫法，依項目分小標或條列，每一項裡寫完整的句子。
   - 一項講一件事，寫成一到三句連貫的話。條件、原因和結果放在同一句，用「因為」「所以」「但」「於是」「而」「只要…就」這類連接詞接起來，一個意思寫完才用句號。
   - 結論和它的根據寫在同一句：先寫在什麼情況、因為什麼，再寫會怎樣。
   - ✕「他很少說話。開口就是命令。沒人敢回嘴。」→ ○「他平常很少開口，一說話多半是在吩咐事情，語氣也不重，底下的人卻從來沒有誰敢回一句。」
2. **正文用流水句**：開場、章節內文與範例對話，用敘事散文的寫法以段落推進，分句之間用因果、轉折或先後接下去，一個意思寫完才用句號。

## 寫給模型的規則
1. **規則以一則回覆做得到的為準，越少越好**。模型一則回覆做得到的是這五種：
   - 這一則發生了某件看得到的事（播種、收成、交付、結帳），把某個值加上或減掉一個寫死的數。
   - 把一個詞換成另一個詞（「已繳」改成「逾期」）。
   - 記「剩幾天」：日期每換一天，把剩下的天數減 1，到 0 時發生該發生的事。
   - 拿現在的值去對一張寫好的表，照表寫結果（累計到 10 是 2 級、到 25 是 3 級；月收入 5000 以下扣 500）。
   - 拿當下看得到的數字算一步（抽成 20%、打八折、兩人平分），規則裡要它把算式和結果寫出來。

   這四種要改寫：回頭數已經過了多久（「七天沒來」「每七天加一週」）改成記「剩幾天」；滿了歸零再進位（「滿 100% 升一級並歸零」）改成累計值加等級表；取餘數改成照表；連續好幾步的算式（先抽成再扣稅再分潤）拆成一步一行，或由動筆的人先算好列成表。

   **一則回覆要算的地方最多兩三處**，算太多模型會漏、會算錯。超過時把結算集中到固定的時點（一天結束、每月一號）一次做，平常只記原始的數字；或把常用的結果先算好列成表。
2. **一句寫一條規則，主詞寫出來**，條件、動作與結果寫在同一句。同一個東西在所有欄位只有一個名字。規則放在它生效的那個欄位，最重要的放最前面。給模型一份清單時寫明要挑幾個。
3. **例子會被照抄**。名字、暱稱這類欄位留給模型生成；要它輸出的格式，直接排出版型給它看。
4. **限制與難度寫成這個世界的常識和角色的理由**。要讓一件事難，寫它在這個世界為什麼難：一般人怎麼看、要付出什麼代價、角色因為哪段經歷很難答應。數值只記錄發生過的事。✕「好感 50 以前一律拒絕」「加的量全部減半」「上限鎖在 30」→ ○ 寫他被騙過、別人對他好時會先想對方要什麼，看到什麼事才會鬆口。

## 自查
寫完逐條對，對不上就回去改，改完再交給使用者。這次用到的那一份檔案有自己的自查時，另外對一次。

1. 每一句都是模型在一則回覆裡做得到的事嗎？時機都綁在看得見的條件上了嗎？
2. 每一句都直接講那件事嗎？抽象的詞、鉤子、懸念都換掉了嗎？
3. 每件事都只寫在一處嗎？
4. 規則都寫成「要做什麼」了嗎？防範句都提出刪除了嗎？
5. 設定都用現在的狀態寫嗎？只在一開始成立的事都放在開局那一章或開場了嗎？
6. 常駐的欄位都只寫方向與感受嗎？清單都是查表用的資料嗎？
7. 結局和角色會變成什麼樣，都留給玩家的行動了嗎？
8. 會破梗的東西都放在玩家看不到的欄位了嗎？
9. 限制與難度都寫成世界的常識和角色的理由了嗎？
10. 寫進作品的文字提到別處時，用的都是那裡的標題或名稱嗎？
11. 設定的每一項都是完整連貫的句子，條件、原因和結果接在同一句嗎？連續的短句與「先下結論再用短句補述」的地方，都併成一句了嗎？
